# Database Context Export

This directory is auto-generated by the `npm run export:schema` script.

It organizes your Supabase project's Postgres schema into:

- `tables/` – One file per table with: DDL, indexes, constraints, RLS enable/force flags, and policies.
- `functions/` – One file per user-defined SQL function (non-aggregates).
- `triggers/` – One file per trigger (non-internal) with the trigger definition.
- `enums/` – One file per enum type with a `CREATE TYPE` statement.

## Usage

1. Provide credentials (see below).
2. Run: `npm run export:schema`
3. Commit the updated SQL artifacts.

## Credentials

For a COMPLETE export (including RLS policies) you must use a direct Postgres connection with a service role password.

Environment variables the script will look for (first found, first used):

- `SUPABASE_DB_PASSWORD` – Preferred. (Service role password from the project settings.)
- `SUPABASE_SERVICE_ROLE_KEY` – Fallback if you reuse it as the DB password (not recommended to store directly in repo).
- `SUPABASE_ANON_KEY` – Only used for a limited pg_meta fallback (missing RLS + some DDL nuances).

Create a local `.env` (never commit secrets):

```
SUPABASE_DB_PASSWORD=your_service_role_password
SUPABASE_SERVICE_ROLE_KEY=your_service_role_key (optional)
SUPABASE_ANON_KEY=your_anon_key (optional)
```

Then run:
```
SUPABASE_DB_PASSWORD=... npm run export:schema
```
(or rely on values loaded by a dotenv loader if you add one.)

## Notes
- If you see `-- Could not fetch pg_get_tabledef`, the helper function/extension isn't available; the rest of the metadata still exports.
- Enum files are idempotent representations (may need `DROP TYPE IF EXISTS` wrapper if replaying in migrations).
- Trigger files only include the trigger definitions; ensure underlying function bodies also exist (they'll be in `functions/`).
- Policies are emitted with explicit roles and USING/WITH CHECK clauses.

## Improving Replay Safety
If you plan to *replay* these definitions in another environment, you may want a build step that wraps statements with `IF NOT EXISTS` or drops existing objects first. This repository currently keeps the raw introspected forms for clarity.

## pg_meta Fallback
If no DB password is provided AND no anon/service key, the script will produce only a fallback note. Provide proper credentials for full fidelity.
